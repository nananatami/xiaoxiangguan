# 翻译输入、输出与断点恢复

## 输入

1. 导入 EPUB、PDF 或 AZW3，提取章节原文；扫描 PDF 按配置使用 OCR。
2. 按空行分段，用章节 ID、段落内容及重复次数生成稳定的段落 ID。
3. 按原文字符数分块，默认目标 3000 字符，可设 500–6000；保持完整段落，超长单段可能超过目标值。精校时还保持已有译文合段与原文的对应关系。
4. 每块单独提交请求：系统消息包含翻译任务、文体、忠实性和输出格式；用户消息包含作品与章节名、术语表、人物表、前章结尾、本章前一块译文末尾，以及本块原文的 `[{id,text}]` 数组。精校额外提供对应初译。

每块的任务说明都明确：只对提供的既有文本作语言转换；涉及敏感描写时保留原文程度，不增添细节、不强化描写，不推定原文未说明的年龄或关系。无法处理时返回独立拒绝字段，不用摘要或拒绝说明冒充译文。

HTTP 后端发送 Chat Completions 或 Responses 请求。CLI 后端通过 stdin 提交提示词，在临时目录运行。OpenCode 本地服务为每块建立会话。当前流程没有让模型调用工具读取原书，也没有通过工具参数提交译文。

## 输出

成功的逻辑格式为：

```json
{"segments":[{"sourceParagraphIds":["p-example-1"],"text":"对应段落的中文译文"}],"refusal":null}
```

可合并相邻段落，但所有源段落 ID 必须恰好出现一次并保持原顺序。拒绝格式为：

```json
{"segments":[],"refusal":"无法处理本块的简短原因"}
```

先检查服务商结束状态和原生拒绝字段，再解析 JSON、检查非空译文和 ID 覆盖。通过后立即保存此块，阅读页逐块展示。全章成功后拼接正文写入 Markdown 译稿，保存带段落映射的历史版本，供阅读和导出 EPUB。人工修改、定稿及导出版本沿用原有保护规则。

结构校验能检查缺失、重复和乱序的段落 ID，不能证明段落内部没有漏译、改写或错误；这些仍需精校或人工核对。自然语言拒绝识别只用于无法解析为 JSON 的响应，避免把文学对白中的拒绝句误当成模型拒绝。

## 失败与恢复

| 结果 | 保存行为 | 恢复方式 |
| --- | --- | --- |
| 正常结束且段落覆盖完整 | 保存完成块和对应引擎信息 | 后续跳过此块 |
| 输出长度耗尽或未正常结束 | 此块失败，保留已有完成块 | 可提高输出上限，再重试此块 |
| 原生拒绝、内容审核拦截或拒绝 JSON | 记录 `MODEL_REFUSAL`，不采用为译文 | 保留断点，交由用户处理 |
| JSON 损坏、段落缺失或乱序 | 此块失败；可取得的响应留作诊断 | 重试整个未完成块 |
| 取消或服务重启 | 保留已持久化完成块 | 从未完成块继续 |

“从未完成块继续”使用当前保存的引擎，允许更改模型、服务地址、协议、输出上限或后端；原来的分块大小保持不变。重用完成块前再次检查段落覆盖。原文指纹、范围、初译/精校模式和基准译稿版本必须一致。

每块分别记录模型与引擎，历史版本保存各块的引擎来源；估算费用按各块原有单价汇总。含 CLI 块或用量不明时不猜测费用。引擎记录不保存 API Key 或 OpenCode 密码。

当前恢复单位是完整翻译块：失败块会重新翻译，不接续截断的半句，也不拼接未闭合 JSON。暂停中的“继续”仍恢复原任务；需要换模型时，先取消并保存引擎设置，再点击“从未完成块继续”。

## 设计选择

按稳定段落 ID 保存和恢复，能够检查重复、缺段和乱序，避免自由文本续写的拼接歧义。结构化格式只表达正文与状态；它不会增加单次输出预算，也不能保证上游内容审核通过。
